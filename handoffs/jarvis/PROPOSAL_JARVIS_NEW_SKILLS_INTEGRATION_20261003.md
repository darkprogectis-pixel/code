## 3. Design (smallest abstraction)
USER QUESTION → `router.route()` (new intents KNOWLEDGE_QUERY, CROSS_SOURCE) → `skills.selectSkills()` → existing corpus `ask()` → evidence rows → grounded pt-BR answer (`answer.mjs`) → TTS (unchanged).
1. **Registry** `config/jarvis-skills.json` (data only): one entry per real skill: `skill_id, name, domain, path, corpus_path, source, retrieval_method (spotgamma-course-ask | alpha-video-ask), api_filter, confidence_policy, enabled, priority, live_state_source`. JARVIS keeps no copy of corpus content.
2. **`tools/jarvis/skills.mjs`** (new, ~150 lines): `loadRegistry()` + validation (unique ids, real paths, corpus present, source); `knowledgeSources(text)` (SpotGamma / MenthorQ / α-name detection; the word "gamma" alone is a concept, not the source); `selectSkills(route)`; `retrieve(skill, query)` calling the two existing `ask()` functions (import, no subprocess, no network); normalisation into evidence rows `{source, skill, concept, statement, lesson|video, timestamp, text_source, api_attribution, confidence}`; local paths are never exposed (video title only). Strict rule: a hit counts only if the query names a glossary concept and the item's concept matches; OCR-only items and statements of fewer than 5 words are ranked out when spoken/first-party text exists. No concept or no match ⇒ `INSUFFICIENT_EVIDENCE`.
3. **Cross-source** `compareSources(a, b)`: per-source answers are always returned separately ("Segundo SpotGamma…", "Segundo MenthorQ…"). Verdict: one or both missing ⇒ INSUFFICIENT_EVIDENCE; both present ⇒ deterministic axis lexicon over the retrieved statements (volatility effect dampen×amplify, level role support×resistance, direction up×down, regime words): same dominant pole ⇒ AGREEMENT; opposite poles ⇒ DIFFERENCE; both poles present / regime-conditioned ⇒ CONTEXT_DEPENDENT; no axis signal ⇒ INSUFFICIENT_EVIDENCE (no artificial consensus). Unresolved corpus contradictions are surfaced as warnings.
4. **Router** (`router.mjs`): definitional phrasing (o que é/são, significa, defin-, explique/explica + concept, como … interpreta/explica/define/usa, para que serve, usado para, o que o curso/a aula diz, segundo o curso) without live cues (onde, agora, atual, valor, quanto) ⇒ KNOWLEDGE_QUERY; knowledge phrasing + both vendors named or compar/diferença/ambas ⇒ CROSS_SOURCE. Checked after CANCEL and FUSION_EXPLANATION, before COMPARISON/LEVEL/FIELD. All existing intents and their test phrases keep routing as today (fallback preserved).
5. **Answer** (`answer.mjs`): KNOWLEDGE_QUERY/CROSS_SOURCE are answered before the Alpha state is loaded (knowledge does not need the live service). Answer quotes the course statement (course language, not translated, so no unsupported paraphrase), with lesson/video + timestamp + uncalibrated confidence. `jarvis-answer/v1` gains `knowledge: {selected_skills, per_source[], comparison, obs}`; `evidence[]` rows carry source/skill/concept/citation. Empty retrieval ⇒ `NO_EVIDENCE` text + status INSUFFICIENT_EVIDENCE.
6. **Observability**: `server.mjs` adds `knowledge: {intent, selected_skills, sources, hit, evidence_count, confidence, retrieval_ms}` to the existing voice-cycle record (no new log file, no new content stored; transcript policy unchanged).
7. **Lexicon**: candidates reviewed, **none promoted** in this DIFF. MenthorQ pairs (jacks→GEX, Q-Moders→Q-Models, data→delta, coal→call) come from English ASR of an English course, not from the operator's pt-BR microphone; "data" is the α Data source alias and "coal/call" would rewrite valid speech ⇒ high risk. "Mentor Q→MenthorQ" and SpotGamma "Hero→HIRO" are **already live** in `voice.mjs STT_FIX`. Others stay candidates. `voice.mjs` unchanged.
8. **Voice**: STT/TTS models, VAD, PTT, wake OFF and barge-in unchanged. Only the text answer path is extended.
